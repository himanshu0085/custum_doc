Hi Team,

During the review of the frontend CI/CD pipelines across **PROD, QA, and UAT**, we observed that several application-level fixes are currently being applied directly within the CI/CD pipelines using commands such as `sed`, `awk`, `rm`, and similar shell operations.

These changes modify frontend source files during pipeline execution instead of being maintained in the frontend source repository. For example, the pipelines are modifying files such as `VehicleList.tsx`, `Conversation.tsx`, `next.config.ts`, negotiation pages/components, `Header.tsx`, `server-request.ts`, and other frontend application files.

To address this, the following action items are proposed with clear ownership between the **Development** and **DevOps** teams.

### Developer Action Items

| # | Action Item                  | Expected Action                                                                                                                                                                           |
| - | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | **Application-Level Fixes**  | Identify and move all application-level fixes currently being applied through `sed`, `awk`, `rm`, or similar commands in PROD, QA, and UAT pipelines into the frontend source repository. |
| 2 | **Unit Test Cases**          | Add/update unit test cases for the affected application functionality and ensure the implemented fixes are covered by appropriate automated tests.                                        |
| 3 | **Application Dependencies** | Review the frontend dependencies and address unnecessary, outdated, or vulnerable dependencies identified during dependency analysis.                                                     |
| 4 | **Application Build**        | Ensure the frontend application builds successfully from the committed source code without requiring application-source modifications from the CI/CD pipeline.                            |
| 5 | **Application Dockerfile**   | Ensure the required frontend Dockerfile is maintained as part of the application source and does not need to be dynamically generated by the CI/CD pipeline.                              |

### DevOps Action Items

| # | Action Item                           | Expected Action                                                                                                                                                  |
| - | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | **CI/CD Pipeline Cleanup**            | Remove application-source modification commands from the PROD, QA, and UAT pipelines after the corresponding developer changes are completed and validated.      |
| 2 | **Unit Test Integration**             | Integrate frontend unit test execution into the CI pipeline and ensure the pipeline does not proceed to the build/deployment stage when the required tests fail. |
| 3 | **Dependency Scanning**               | Implement automated dependency/SCA scanning and configure appropriate vulnerability thresholds for the frontend dependencies.                                    |
| 4 | **Secret / Git Leak Scanning**        | Implement secret scanning/Git leak detection to identify credentials, tokens, keys, or other sensitive information committed to the repository.                  |
| 5 | **Container Image Scanning**          | Integrate **Trivy** container image scanning and validate the image for OS-level and application/library vulnerabilities before deployment.                      |
| 6 | **Container Image Size Optimization** | Review and optimize the frontend container image size by removing unnecessary dependencies, files, caches, and build artifacts from the final runtime image.     |
| 7 | **CI/CD Standardization**             | Standardize the frontend CI/CD process across PROD, QA, and UAT for build, testing, security scanning, image creation, and deployment.                           |

### Execution Dependency

**Developer Changes → Unit Test & Application Validation → DevOps CI/CD Changes → Security & Container Scanning → Deployment**

The objective is to ensure that **application fixes, application dependencies, unit tests, and application build requirements remain part of the frontend source repository**, while **CI/CD execution, security scanning, container image validation, image optimization, and deployment remain under DevOps ownership**.
